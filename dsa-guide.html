Complexity & correctness primer

Before patterns: three habits that separate a working solution from an interview-grade one.

HabitWhat to say out loud
Invariant"After each step, property P still holds" (e.g. every dequeued BFS cell has min distance).
ComplexityTime and space in terms of input size — grid R×C, graph V+E, array n.
TradeoffWhen you'd pick DFS vs BFS, DP table vs two variables, recursion vs iteration.

Big-O refresher (tight bounds)

  • O(1) — constant work (hash lookup, stack push).
  • O(log n) — binary search / tree height on balanced data.
  • O(n) — one pass; monotonic stack each index push/pop once.
  • O(n log n) — sorting-based greedy / merge sort.
  • O(n²) / O(RC) — nested loops or full grid scan.
  • O(2ⁿ) — naive backtracking over subsets (fine for small n).

Proof habit (short)

State the invariant → show it holds at init → show one step preserves it → conclude at termination. Interviewers want the sketch, not a textbook proof.

DFS — Depth-First Search

One sentence: Go as deep as possible along one path, then backtrack and try the next branch — like walking a maze and always taking the first open turn until you hit a wall.

Real-life analogy

You're exploring a building floor plan with a pen. Enter a room, mark it visited, open the first door, keep going until every reachable room from that entrance is marked. That's one "connected component." Start again from any unmarked room for the next component.

Worked example — Number of Islands

Problem in one line: Count how many separate land blobs ('1' cells connected up/down/left/right) are on the grid.

WhatIn this demoWhat it means
Input 2D grid of '1'/'0' 4×5 grid with two land blobs Land cells to explore; water is ignored
Output one integer — island count 2 Two disconnected land regions (not cell count)

What the output is not: not the number of land cells, not a path. Each DFS flood fill = one island.

Annotated C reference

/* Grid DFS — 4 directions */
void dfs(char g[][COLS], int rows, int cols, int r, int c) {
    /* 1. BASE CASE — stop if out of bounds or not land */
    if (r < 0 || r >= rows || c < 0 || c >= cols) return;
    if (g[r][c] != '1') return;

    /* 2. MARK VISITED — sink so we don't revisit */
    g[r][c] = '0';

    /* 3. RECURSE — try all 4 neighbors */
    dfs(g, rows, cols, r + 1, c);
    dfs(g, rows, cols, r - 1, c);
    dfs(g, rows, cols, r, c + 1);
    dfs(g, rows, cols, r, c - 1);
}

Line-by-line trace (first call dfs(g, 4, 5, 0, 0))

  1. Enter (0,0): in bounds, g[0][0]=='1' → set to '0'
  2. Recurse down: dfs(1,0) → same island, mark and continue
  3. Recurse right: from (0,0) also try (0,1), (0,2) … entire blob gets sunk
  4. Return: when all four recursive calls finish, this cell's DFS is done
  5. Outer loop (in main's helper): scan grid; next '1' at (3,3) starts a new island count
Use DFS when: counting connected regions, exploring all paths, tree recursion (left/right), or mutating the grid in place.
Tree example: Tree Path Sum (q120) — recurse left and right with a smaller target.

Invariant

Every cell that is currently '0' (after sinking) was land that already belongs to a counted island; DFS never revisits a sunk cell.

Complexity

Time O(R·C) — each cell entered at most once. Space O(R·C) worst-case recursion depth on a snake-shaped island (use explicit stack if stack depth is a concern).

Correctness sketch

Connected components under 4-adjacency partition the land cells. Flood fill from an unmarked land cell marks exactly one component; the outer scan counts how many times a new component starts.

Edge cases

  • Empty grid / all water → 0 islands
  • Single cell land → 1
  • Diagonal-only neighbors are not connected (unless problem says 8-dir)

Interview traps

  • Forgetting the base case → infinite recursion
  • Using BFS when you only need a count (works, but DFS is shorter in C)
  • Marking visited after enqueueing neighbors incorrectly in iterative variants

Related classic algorithms

Flood fill (paint bucket), connected components in graphs, Union-Find as an alternative when merges matter.

BFS — Breadth-First Search

One sentence: Explore in expanding rings — all cells 1 step away first, then 2 steps, then 3. The first time you reach the goal, you have the shortest path (on an unweighted grid).

Real-life analogy

Ripples in a pond. Drop a stone at the start — the wave hits nearby cells first. BFS uses a queue (FIFO: first in, first out) so cells are processed in order of distance.

Worked example — Shortest Path in Grid

Problem in one line: From top-left to a goal cell, move to open neighbors only — what is the fewest steps?

WhatIn this demoWhat it means
Input grid, start, goal, walls 5×5, start (0,0), goal (4,4), wall column Where you can walk; walls block
Output one integer — distance distance when goal is first dequeued Shortest step count (BFS guarantee on unweighted grid)

What the output is not: not “any path length,” not number of cells visited. First time you dequeue the goal = answer.

C code (highlight follows Next)

Annotated C reference

/* Queue arrays live outside or as static — but head/tail reset EACH call */
int q_r[MAX_CELLS], q_c[MAX_CELLS], q_d[MAX_CELLS];

int shortestPath(char g[ROWS][COLS], int goal_r, int goal_c) {
    /* FIX: reset head/tail inside helper — not as globals */
    int head = 0;
    int tail = 0;
    int vis[ROWS][COLS] = {0};

    q_r[tail] = 0; q_c[tail] = 0; q_d[tail] = 1;
    tail++;
    vis[0][0] = 1;

    while (head < tail) {
        int r = q_r[head];
        int c = q_c[head];
        int d = q_d[head];
        head++;

        if (r == goal_r && c == goal_c) return d;

        /* for each open neighbor: if (!vis[nr][nc]) { vis[nr][nc]=1; enqueue(nr,nc,d+1); } */
    }
    return -1;   /* goal unreachable */
}

Line-by-line trace

  1. Enqueue (0,0) dist=1 — queue is not empty, so BFS can run
  2. Dequeue front — process the oldest cell first (that's what makes it "breadth" first)
  3. Push neighbors with dist+1 only if unvisited — mark in vis[][]
  4. Goal check when dequeuing — not when enqueueing — so distance is correct
Use BFS when: shortest steps on a grid, level-order traversal, or "minimum number of moves."

Invariant

When a cell is dequeued, its distance is the minimum number of steps from the start on an unweighted grid (edges cost 1).

Complexity

Time/space O(R·C). Queue holds at most O(R·C) cells. Equivalent graph view: O(V+E) with V=R·C and E≤4V.

Correctness sketch

BFS expands by nondecreasing distance. First visit = first time the wavefront reaches the cell = shortest path (induction on distance layers).

Edge cases

  • Start == goal → return 1 (or 0 depending on problem definition — clarify)
  • Blocked start/goal → -1
  • Walls that disconnect the grid → unreachable

Interview traps

  • Using DFS for "shortest" — wrong on unweighted grids with detours
  • Global head/tail not reset between calls
  • Marking visited too late → exponential re-enqueues

Related classic algorithms

Level-order tree traversal, 0-1 BFS (deque) when edges are 0/1, Dijkstra when edge weights vary.

DFS vs BFS — quick comparison

DFS

  • Stack (implicit via recursion) or explicit stack
  • Goes deep first
  • Great for: flood fill, all paths, trees
  • Does not guarantee shortest path

BFS

  • Queue (head / tail)
  • Expands layer by layer
  • Great for: shortest path on unweighted grid
  • Uses more memory at wide layers
Tree DFS

Trees — same DFS idea, different shape

One sentence: A binary tree is nodes with left and right pointers. DFS on a tree = recurse into children instead of grid neighbors.

Grid DFS visits 4 neighbors. Tree DFS usually visits 2 children. The base case is root == NULL. Leaf = both children are NULL.

C code (highlight follows Next)

Annotated C reference

struct Node { int val; struct Node *left, *right; };

int hasPathSum(struct Node *root, int target) {
    if (!root) return 0;
    if (!root->left && !root->right)
        return root->val == target;   /* leaf */
    return hasPathSum(root->left, target - root->val)
        || hasPathSum(root->right, target - root->val);
}

BST insert/search/traverse live in the Binary Search Tree category (q63–q70). Tree path sum is the bridge from grid DFS to pointer recursion.

Invariant

At node u with remaining target T, there exists a root→leaf path through u summing to the original target iff a leaf path in the subtree sums to T.

Complexity

Time O(n) nodes visited once (early exit if short-circuiting on success). Space O(h) recursion height.

Correctness sketch

Leaf check is exact. Internal nodes OR left/right after subtracting val — covers every root→leaf path exactly once.

Edge cases

  • root == NULL → false
  • Single-node tree → compare val == target
  • Negative values allowed → don't prune on remaining < 0 unless problem forbids negatives

Interview traps

  • Checking sum only at non-leaves
  • Confusing "any path" with "root-to-leaf only"

Related classic algorithms

Tree DFS, path sum variants, binary tree maximum path sum (harder — any node-to-node).

Table / recurrence

Dynamic programming (DP)

One sentence: Save answers to smaller sub-problems in an array so you never recalculate them from scratch.

Real-life analogy

You write down "1+1+1+1+1 = 5" on paper. When someone adds another "+1", you don't count from the beginning — you use the 5 you already wrote and add 1 to get 6. DP is that scratch paper as an array.

How to think

DP is not a special library or keyword in C. It's a recipe:

  1. Define dp[i] in English: "number of ways to reach stair i" or "best loot using houses 0..i"
  2. Find the recurrence: how does dp[i] relate to smaller indices?
  3. Base cases: dp[0], dp[1] you know by hand
  4. Fill the table left to right (or nested loops for 2-D)

The 3 ways to implement DP (all covered in the demo)

Same math — three coding styles. Names people mix up:

TypeAlso calledHow it runsC shape
1. Top-down + memo Memoization Ask for big answer → recurse to smaller → cache each answer in an array int memo[N]; recursive f(i) with if (memo[i]!=-1) return
2. Bottom-up table Tabulation Start at base cases → loop fills dp[0..n] for (i=…) dp[i] = …
3. Space-optimized Rolling variables / O(1) DP Same as bottom-up, but only keep the last 1–2 rows/values int a,b,c; slide window each step

Note: “Top-down” without a cache is just recursion — usually exponential. Memoization = top-down + cache. Bottom-up is the same recurrence filled with a loop.

How to recognize “this is a DP question”

Look for overlapping choices you would recompute. Checklist:

Signal in the problemWhy it smells like DPExample
“How many ways…” / “count distinct…”Sum of ways of smaller statesClimbing Stairs
“Minimum / maximum …” with choicesOptimal substructure — best of smaller decisionsCoin Change, House Robber
“Cannot take adjacent / with constraint”State needs previous decisions encodedHouse Robber
Brute force = try all subsets / recursions that repeat workOverlapping subproblemsNaive fib / coin recurse
Answer for n depends only on answers for smaller nYou can fill a table in orderAll classic 1-D DP
Not DP when: a single greedy pass is enough (Jump Game farthest), or you only need any path / flood fill (DFS), or shortest unweighted steps (BFS). If sorting + one pass solves it, try greedy first.

Which DP type should I pick?

Key decision: write the recurrence first, then pick the implementation style.

Question / patternKey thing that decidesPreferWhy
Climbing Stairs Only needs last 2 values; linear order clear Space-opt (or bottom-up) Interview favorite: two ints, no array
House Robber Choice at i uses best of i−1 and i−2 Space-opt / bottom-up Same rolling window as stairs
Coin Change Need all amounts 0…amount; nested coin loop Bottom-up table Natural fill order; memo recurse works but messier in C
Tree / graph DP (path counts on trees) Structure is recursive, not a flat index Top-down + memo Follow tree shape; cache by node id / state
Hard state (subset mask, multi params) Only some states reachable Top-down + memo Don’t allocate huge unused tables
Small n, need full table for debug You want to print dp[] Bottom-up Easiest to trace in interviews
Memory tight / embedded Recurrence only depends on last k rows Space-opt O(1) or O(k) instead of O(n)

Decision flow (say this in an interview)

  1. Is there optimal substructure + overlapping subproblems? → DP.
  2. Write dp[state] in one English sentence.
  3. Write the recurrence + bases.
  4. If states are a simple 0…n (or 2-D grid) → bottom-up. If tree/sparse → top-down memo.
  5. If recurrence only needs last few answers → space-optimize.

Worked example — Climbing Stairs

Problem in one line: You can climb 1 or 2 stairs at a time. How many distinct sequences reach the top?

WhatIn this demoWhat it means
Input n — number of stairs n = 5 There are 5 steps from ground to top
Output one integer — number of ways 8 There are 8 different step sequences that sum to 5

What the output is not: not the number of stairs, not the min steps (that would be 3 via 2+2+1). It is a count of sequences.

All 8 ways for n=5 (1 = single step, 2 = double):

1+1+1+1+1
1+1+1+2   ·  1+1+2+1  ·  1+2+1+1  ·  2+1+1+1
1+2+2     ·  2+1+2    ·  2+2+1
→ 8 sequences. Order matters: 1+2+2 ≠ 2+1+2.

Why DP? Because ways(5) = ways(4)+ways(3): last step was either a 1 (came from stair 4) or a 2 (came from stair 3).

Default for C interviews: start with bottom-up (clear loop, easy to debug). Compress to space-opt if you only need the last row/values. Use top-down + memo when the state space is a tree or sparse (“only recurse what you need”).

Invariant (stairs)

After processing index i, dp[i] equals the number of distinct ways to reach stair i with steps in {1,2}.

Complexity

Tabulation: time O(n), space O(n) or O(1) with two variables. Memoized recursion: same asymptotic, different constant factors and stack use.

Correctness sketch

Last step onto i is either from i-1 or i-2; those sets of paths are disjoint and cover all ways → recurrence is exact (Fibonacci).

Edge cases

  • n = 0 / n = 1 — define with interviewer (often return 1)
  • Large n — overflow int; may need long long or mod

Interview traps

  • Exponential recursion without memo
  • Off-by-one base cases (dp[0] vs dp[1])
  • Confusing "ways" with "min steps"

Related classic algorithms

Fibonacci, 1-D DP, knapsack / coin change (unbounded), house robber (choice DP).

One pass

Greedy

One sentence: Make the best local choice at each step and hope those immediate jumps lead to the global best — often one loop, one variable, no table.

Real-life analogy

Climbing a hill in pitch-black fog. You can't see the summit — only your feet. Each step, pick the direction that goes steepest upward right now. Greedy never reconsiders past choices.

Worked example — Jump Game

Problem in one line: From index 0, each cell says how far you may jump — can you reach the last index?

WhatIn this demoWhat it means
Input array nums [2,3,1,1,4] nums[i] = max jump length from i
Output 1 or 0 1 (yes) Last index is reachable by some jump sequence

What the output is not: not minimum jumps (that’s a harder variant), not the path. Just yes/no.

Step 1 / ?

C code (highlight follows Next)

Annotated C reference

int canJump(int *nums, int numsSize) {
    int maxReachable = 0;

    for (int i = 0; i < numsSize; i++) {
        if (i > maxReachable) return 0;   /* stuck — can't reach i */

        int currentReach = i + nums[i];
        if (currentReach > maxReachable)
            maxReachable = currentReach;

        if (maxReachable >= numsSize - 1) return 1;
    }
    return 0;
}

Line-by-line trace

  1. Horizon: maxReachable = 0 — furthest index you can touch.
  2. Scan: if current index i is past that horizon, you're stuck → return 0.
  3. Local choice: update horizon with i + nums[i]; early exit once horizon passes the last index.

Interval problems (q117, q122) use the same spirit: sort by end time, keep the greedy choice, one pass.

Invariant

After scanning indices 0..i (with i ≤ maxReachable), every index ≤ maxReachable is reachable from 0 by some jump sequence.

Complexity

Time O(n), space O(1).

Correctness sketch

If the end is reachable, there is a first index that reaches it; expanding the farthest frontier never skips a necessary landing pad inside the reachable prefix. If the scan hits i > maxReachable, a gap exists → impossible.

Edge cases

  • n = 1 → always true
  • nums[0] = 0 and n > 1 → false
  • Zeros in the middle that block the frontier

Interview traps

  • Simulating every jump path (exponential)
  • DP can[i] works but is slower to write under time pressure

Related classic algorithms

Interval covering, activity selection (sort by end), Huffman-style local choices when greedy choice property holds.

Stack

Monotonic stack

One sentence: Keep a stack sorted in one direction (increasing or decreasing) to find the "next greater" or "next smaller" element in O(n) time.

Real-life analogy

People in a single-file line. A tall person joins at the back — they block the view of everyone shorter in front of them from a back-to-front perspective. The stack holds who still "matters" when scanning backward.

Worked example — Daily Temperatures

Problem in one line: For each day, how many days until a warmer temperature? (0 if none.)

WhatIn this demoWhat it means
Input array of daily temps [73,74,75,71,69,72,76] One number per day
Output array wait[] same length [1,1,4,2,1,1,0] wait[i] = days until warmer than day i

What the output is not: not the warmer temperature itself — the distance in days.

C code (highlight follows Next)

Annotated C reference (next greater — scan right to left)

void nextGreaterElement(int *nums, int size, int *result) {
    int stack[size];
    int top = -1;

    for (int i = size - 1; i >= 0; i--) {
        while (top >= 0 && stack[top] <= nums[i])
            top--;                          /* pop smaller — can't be next greater */

        result[i] = (top == -1) ? -1 : stack[top];
        stack[++top] = nums[i];
    }
}

Line-by-line trace

  1. Setup: array stack[] + top = -1 (empty stack).
  2. Backward scan: start at the last index — each step asks "what's the next greater to my right?"
  3. Pop smaller: while stack top ≤ current value, pop — those values are useless for anything left of here.
  4. Answer & push: stack top (if any) is the next greater; push current value for future indices.

Variant — Daily Temperatures (forward scan, index stack)

int stack[MAX], top = -1;

for (int i = 0; i < n; i++) {
    while (top >= 0 && T[i] > T[stack[top]]) {
        int prev = stack[top--];
        wait[prev] = i - prev;
    }
    stack[++top] = i;
}

Invariant

Stack values are strictly decreasing (or increasing, depending on variant) from bottom to top; every popped element has found its next greater (or warmer) candidate.

Complexity

Time O(n) — each index pushed and popped at most once. Space O(n).

Correctness sketch

When scanning right→left, the stack holds candidates to the right in increasing order of position. Smaller values can never be "next greater" for anything further left, so popping them is safe.

Edge cases

  • Strictly decreasing array → all answers -1 / 0 wait
  • Duplicates — decide < vs ≤ carefully

Interview traps

  • Storing values when you need indices (for distance = i - prev)
  • Wrong scan direction for the variant

Related classic algorithms

Next greater element, histogram largest rectangle, stock span — all monotonic stack family.

Search

Backtracking

One sentence: Build a solution step by step; when a path breaks a rule, undo the last choice and try the next branch.

Real-life analogy

A ring of unlabelled keys on a locked door. Try one key, turn it, doesn't work — pull it back out and try the next. Backtracking is that choose → explore → unchoose loop in code.

How it differs from grid DFS

Grid DFS marks cells permanently (sink to '0'). Backtracking un-does each pick so another branch can reuse the same slot. Classic for subsets, permutations, N-queens.

Worked example — Subsets

Problem in one line: List every subset of an array (the power set), including empty and full.

WhatIn this demoWhat it means
Input array of numbers [1, 2, 3] Elements you may include or skip
Output list of all subsets 8 subsets (2³) Every combination: {}, {1}, {1,2}, … {1,2,3}

What the output is not: not permutations (order of picks is fixed by index). Choose → explore → unchoose builds each set.

Step 1 / ?

C code (highlight follows Next)

Annotated C reference

void backtrack(int *nums, int size, int start,
               int *currentSet, int setSize) {
    printSubset(currentSet, setSize);   /* base: record current state */

    for (int i = start; i < size; i++) {
        currentSet[setSize] = nums[i];              /* CHOOSE */
        backtrack(nums, size, i + 1, currentSet, setSize + 1);  /* EXPLORE */
        /* UNCHOOSE — next loop overwrites slot; setSize shrinks on return */
    }
}

Line-by-line trace

  1. Base: every call records the current subset (including empty).
  2. Start index: start prevents duplicates — only pick forward in the array.
  3. Branch: append nums[i], recurse with i+1; when that returns, loop tries the next i.

Invariant

At call with start, currentSet[0..setSize) is a valid subset using only indices < start from earlier choices; the loop extends it without duplicates.

Complexity

Time O(n·2ⁿ) if you copy each subset, or Θ(2ⁿ) if you only count. Space O(n) recursion + path buffer.

Correctness sketch

Every subset S has a unique sorted index sequence; the start pointer generates each sequence exactly once (combinatorial tree of include-next decisions).

Edge cases

  • Empty input → one empty subset
  • Duplicates in nums → need sort + skip (not in q123)

Interview traps

  • Forgetting to record the empty subset
  • Using i instead of i+1 → infinite / duplicates

Related classic algorithms

Permutations, combination sum, N-queens, Sudoku — same choose/explore/unchoose template.

Runtime cheat sheet

  • Binary search — O(log n) time, O(1) space on sorted arrays
  • Two pointers — O(n) time, O(1) space (one pass from both ends or slow/fast)
  • Sliding window — O(n) time, O(1) or O(k) space for frequency table
  • Hash / frequency — O(n) time, O(n) space for count arrays
  • Kadane (max subarray) — O(n) time, O(1) space
  • DFS / BFS on grid — O(rows × cols) time and visit array
  • DP tabulation — O(n) or O(n×m) time, O(n) space (often reducible)
  • Monotonic stack — O(n) time — each index pushed/popped once
  • Backtracking — often O(2n) or O(n!) — fine for small n in interviews

Firmware / drivers

Systems-level & low-level algorithmic patterns

Classic DSA assumes heap freedom and pointer-heavy structures. In kernel, driver, and firmware work, algorithms run under tighter rules: no malloc in hot paths, predictable latency, and memory that sits next to hardware (DMA rings, UART FIFOs, GPIO registers).

6.1 Zero-copy stream parsing

One sentence: Walk a fixed byte buffer with a cursor — expose slices as pointers and lengths instead of copying into new arrays.

Sliding window on strings is the interview version. On UART/SPI/Wi-Fi/BLE you parse frame headers, length fields, and CRC bytes in place over a DMA or ring buffer. No memcpy per field.

Core mechanics: dual pointers over static storage — sync word hunt, length check, advance cursor past frame boundary.

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

typedef struct {
    uint16_t preamble;
    uint8_t payload_len;
    const uint8_t *payload;  /* points into DMA/ring buffer — no copy */
    uint8_t crc;
} zero_copy_frame_t;

bool parse_next_frame(const uint8_t *buffer, size_t buffer_len,
                      size_t *cursor, zero_copy_frame_t *out) {
    while (*cursor + 4 <= buffer_len) {
        uint16_t sync = (buffer[*cursor] << 8) | buffer[*cursor + 1];
        if (sync == 0xAA55) {
            uint8_t len = buffer[*cursor + 2];
            if (*cursor + 4 + len <= buffer_len) {
                out->preamble = sync;
                out->payload_len = len;
                out->payload = &buffer[*cursor + 3];
                out->crc = buffer[*cursor + 3 + len];
                *cursor += 4 + len;
                return true;
            }
            return false;  /* incomplete frame — wait for more bytes */
        }
        (*cursor)++;  /* slide 1 byte and hunt sync again */
    }
    return false;
}

6.2 Bitwise invariants & combinatorial state

One sentence: Replace fat lookup tables with bitmasks — one uint32_t can hold dozens of on/off flags.

Interviewers use this to test whether you think about cycles and RAM, not just big-O on paper.

  • Clear lowest set bit: x & (x - 1) — loop runs once per set bit, not per bit width.
  • GPIO / IRQ masks: enable, disable, or test groups of pins with OR/AND in one instruction.
  • Subset enumeration: iterate mask from 0 to (1<<n)-1 for small n instead of recursion.
#include <stdint.h>

/* Count set bits in O(number of set bits) — Brian Kernighan */
uint32_t count_active_flags(uint32_t status_register) {
    uint32_t count = 0;
    while (status_register > 0) {
        status_register &= (status_register - 1);
        count++;
    }
    return count;
}

6.3 Fixed-size circular ring buffers

One sentence: FIFO with a fixed array — head/tail wrap with modulo (or bitmask when size is power of 2).

Linked-list queues call malloc per node — bad for ISRs and long-running firmware (fragmentation + jitter). A ring buffer is O(1) push/pop with predictable memory.

Power-of-2 trick: if SIZE = 256, use (idx + 1) & (SIZE - 1) instead of % SIZE — cheaper in interrupt handlers.

#include <stdint.h>
#include <stdbool.h>

#define BUFFER_SIZE 256       /* must be power of 2 */
#define BUFFER_MASK (BUFFER_SIZE - 1)

typedef struct {
    uint8_t storage[BUFFER_SIZE];
    volatile uint32_t head;
    volatile uint32_t tail;
} lockless_ring_buffer_t;

bool ring_buffer_push(lockless_ring_buffer_t *buf, uint8_t data) {
    uint32_t next_head = (buf->head + 1) & BUFFER_MASK;
    if (next_head == buf->tail) return false;  /* full */
    buf->storage[buf->head] = data;
    buf->head = next_head;
    return true;
}

bool ring_buffer_pop(lockless_ring_buffer_t *buf, uint8_t *out_data) {
    if (buf->tail == buf->head) return false;  /* empty */
    *out_data = buf->storage[buf->tail];
    buf->tail = (buf->tail + 1) & BUFFER_MASK;
    return true;
}

6.4 Cache-conscious layouts (array heaps)

One sentence: Store trees and heaps in flat arrays so child nodes sit in contiguous cache lines — fewer pointer chases.

Pointer-based BST nodes scatter across the heap → cache misses dominate at scale. A binary heap (or level-order tree) in int heap[] uses index math only:

  • Left child of i → 2*i + 1
  • Right child of i → 2*i + 2
  • Parent of i → (i - 1) / 2

Same idea as heap sort and priority queues in embedded schedulers — no struct Node * required in the hot path.

Practice: q26 Heap sort q63 BST (pointer form) — compare with array indexing when you need speed.

Systems DSA interview checklist

State these out loud before you code — interviewers notice:

  1. No heap in hot path: "I'll avoid malloc/free here for deterministic timing and no fragmentation."
  2. Prefer iteration: "I'll use a loop instead of deep recursion so stack usage stays bounded in kernel/ISR context."
  3. Concurrency: "If this runs in an ISR, I'll use a lock-free ring or document where a memory fence is needed."

ISR / lock-free caveats

  • Single-producer / single-consumer rings can be lock-free with careful volatile + memory barriers; multi-producer needs atomics or locks.
  • volatile alone is not a concurrency primitive — it prevents compiler elision of MMIO/status reads, not reordering across cores.
  • Power-of-2 masks hide bugs if size is not actually 2ⁿ — assert it.
  • Zero-copy pointers into DMA buffers are invalid after the buffer is recycled — document lifetime.
